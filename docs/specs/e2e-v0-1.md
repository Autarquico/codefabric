# E2E v0.1

## Contexto / problema

Milestone de la [Fase 1 — Workers y ejecución básica](phase-1-workers.md). Implementa §42.4 (1, 2, 3, 11, 14), Done de Fase 1 de `docs/codefabric-spec.md`.

Owner previsto en el bucle Develop: qa-tester y devops-eng.

## Scope

**Entra:**
- `internal/e2e`: orquestador de procesos (Controller + 2 Workers), `netproxy` para particiones, helpers sobre `cf --json`

**No entra:**
- Nada fuera de lo indicado en la epic.

## Criterios de aceptación

Cada scenario se implementa como un test `TestScenario_*`.

### Scenario: Done de Fase 1
- **Given** dos Workers
- **When** se ejecuta `cf do -- <cmd>`
- **Then** corre en uno de ellos y se observa desde un tercer cliente

### Scenario: Crash del Controller
- **Given** un Run en curso
- **When** `kill -9` al Controller
- **Then** no se pierde ni se duplica el Run ni su resultado

### Scenario: Crash del daemon (e2e #14)
- **Given** un Run en curso
- **When** `kill -9` al daemon del Worker
- **Then** no se pierde ni se duplica y el journal no reutiliza secuencias

### Scenario: Partición (e2e #11)
- **Given** una partición que dura hasta reasignar la lease
- **When** el Worker original vuelve
- **Then** su proceso queda huérfano, nunca duplicado

## Notas técnicas / riesgos

- Respetar las reglas de capas (ADR 0001) y las decisiones D1–D7 (ADR 0002).
- Transacción única para estado, evento e idempotencia (§27.4); reloj inyectable en todo timeout.
